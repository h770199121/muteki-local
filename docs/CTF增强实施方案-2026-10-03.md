# CTF 工具验收与增强实施方案

日期：2026-10-03。承接《CTF能力增强仓库调研-2026-10-03.md》及[上游同步评估](上游同步评估-2026-10-03.md)。这是 FishCodeTech/muteki 改造的完全离线、本地模型、轻量化版本；保留现有 Coordinator 和独立 Flag gate。

**当前决策边界：本次仅补充实施方案，由用户决定后续是否修改。下方候选项均未因写入文档而获得实施授权；此前已完成的工具增强及上游回移保留为历史记录。用户可以选择实施、仅做对照试验、暂缓或不做某项，不必一次接受整套方案。**

本文环境、端口和工具状态引用此前的检查结果，本次没有重新探测服务，也没有修改源码、模型/网络配置、依赖或部署。

## 完全离线与轻量化约束

- 运行时只使用预装依赖、已冻结的本地资料、本地模型以及允许的本地靶场。云端难点审查不属于本版本方案。
- 区分“模型在本机”与“运行时没有公网依赖”：现有 bridge 网络和网页工具开关并不能单独证明网络隔离。需另行验收端点限定、禁止云端回退、离线依赖、模型与本地靶场的可达性。
- 保留通用代码作为可用基础，逐步减少单 Worker 不需要的图调度、角色提示、额外模型调用和重复依赖；不为追求轻量化删除证据、预算和结果校验。
- 文档研究/依赖准备可以在部署前完成；最终离线交付要有版本清单和验收结果，运行时不执行在线安装或更新。

## 验收层次

1. **镜像与路径**：检查正在运行的控制面实际选择哪个 Worker 镜像、运行用户、PATH、SDK、知识目录和工具入口。
2. **真实工具操作**：临时隔离容器中使用自产无害夹具，验证命令及依赖能完成具体操作；版本号或 import 成功只能说明对应层次。
3. **Agent 调用协议**：通过实际 dsh SDK/Muteki 事件桥接执行本地工具，检查 tool call/result 对应关系、原始结果和工作目录。确定性模型接口回放与真实本地模型验证分开报告。
4. **题目能力**：冻结模型、镜像、技能和预算，使用独立留出题，重复评测。工具验收通过不等于 CTF 解题率提升。

## 初始基线

- 目录无 Git 元数据；对拟修改文件保留本轮可恢复副本和 SHA-256 清单。
- 当时运行的 web-api 实际选择 `ghcr.io/fishcodetech/muteki-worker:zcode`，不是凭 Dockerfile 推断的 latest 镜像。
- 实际镜像：Python 3.14.6、uid 1000（kali）、dsh SDK 0.1.0rc6。
- 已发现路径问题：`analyzeHeadless` 不在 PATH，但 `/usr/share/ghidra/support/analyzeHeadless` 存在；Volatility 入口是 `vol`，没有 `vol3`。
- `nuclei`、`zbarimg`、`zsteg` 不在当前镜像 PATH；不能继续笼统宣称完整工具表均可直接运行。
- 18210 未发现监听进程，本轮开始时不能直接验收配置的真实本地模型。先完成工具和协议层检查，真实模型验证单列。
- 宿主项目 venv 没有 pytest；优先使用标准库 unittest 跑新增定向回归，现有 pytest 测试在具备依赖的项目环境执行。

### D01：完全离线运行契约

**依据与范围：** 本地模型配置不等于整个系统没有公网依赖。检查 Worker、Coordinator/planner、摘要、标题及 follow-up 的所有模型入口；涉及 `apps/web/worker_config.py`、`apps/web/drivers.py`、`muteki/core/llm.py`、dsh 桥接和启动/容器配置。

**拟实施：** 显式声明本地模式及允许的模型、靶场和本地服务地址；端点缺失/不可达时返回可定位错误，禁止回退默认云端 provider。启动只使用已有镜像和冻结依赖，禁止运行中自动安装/更新。网络限制须同时覆盖 shell 工具与模型请求，不能仅关 WebSearch；也不能直接将所有 Worker 改成 `--network none`，因为这可能切断 `host.docker.internal` 和本地靶场。

**验收：** 正常本地任务可执行；停止本地模型后明确失败；缺失依赖时不联网补装；在不依赖公网连通的环境中，运行、恢复和读取本地知识均成功，并保留网络/端点检查证据。

**由用户决定：** 本地服务与靶场允许清单；是否将“进程级禁止公网访问”也作为硬要求。未明确前记为 `missing_requirements`，不猜测允许网段。回滚保留原网络和启动配置快照。

### D02：上下文预算与完整文件交付

**依据与范围：** 必要描述的 600/1000 字符截断已移除，过大 argv 已能报错；但当前尚未解决“文本完整而过长”。涉及 `cli_solver.py`、调用传输、Worker 工作空间与上下文记录，可借鉴上游 required/optional sections 和 context manifest。

**拟实施：** 必要题意、目标约束和最新人工指令完整保留；历史日志、重复事实、可选资料按明确优先级装配。长文和原始工具输出保存在 Worker 可读文件，交付精确指针及有限预览；记录本次实际送达的章节、源文件、长度和被省略的可选内容。上下文容量来自本地模型服务/显式配置，不统一假定为 262K。只有实际验证支持的执行器才启用相应 stdin/文件传输，不能将通用 stdin 冒烟结果当作所有 dsh 会话语义的证明。

**验收：** 长描述尾部条件、编码字节、跨容器路径、恢复后指针均可核对；超预算明确说明缺口而非静默裁剪；在相同题目与预算下记录输入规模、首个有效动作时间和证据遗漏。

**由用户决定：** 实际上下文窗口、输出预留、哪些人工/题目字段必须原样送达；缺少数值时先列配置需求。主要风险是文件已落盘但模型没读到，需用读取/使用证据验证。

### D03：按题型提示与单 Worker 精简

**依据与范围：** 当前只有单 dsh Worker，SDK 实测只暴露 5 个工具；全局 CTF 提示仍含蜂群措辞和 Web 检查清单。重点检查 prompt 和额外 LLM 调用，不盲目缩减工具接口。

**拟实施：** 按 Web/Crypto/Reverse/Pwn/Forensics/Misc 下发最短相关流程，保留跨题型转向入口。初始上下文已交付的状态不反复全文重读；新 operator directive 仍须及时送达。planner/反思按新证据或明确停滞触发，不增加常驻弱模型角色。先通过配置或独立评测臂比较，保持现有产品 Coordinator 默认。

**验收：** 六类代表题均收到相关提示；人工新指令不会被略过；比较相同预算下的输入/输出 token、重复动作、规划调用和解题结果，而非仅比较提示长度。

**由用户决定：** 仅精简提示，还是同时试验单 Worker 调度；是否保留当前默认、先作对照。D02 提供上下文计量基础，D10 负责评测。

### D04：启动失败、无进展与停滞治理

**依据与范围：** 上游已区分进程未启动、运行中失败和无新证据；本地已有反思/中断逻辑，不能再叠一套冲突计数。涉及 `coordinator_loop.py`、派发、Worker 结束处理与事件。

**拟实施：** 按失败阶段记录原因；相同错误配置不无条件反复派发；只在收到真实进程启动凭据后清零启动失败计数。无新事实、无可执行方向时明确结束/等待配置修复；“模型没有新想法”与“目标或运行时不可用”分开。探测重复性时比较规范化动作与响应，不把确有状态变化的重试误删。

**验收：** 不可用模型、无法准备技能、进程启动后崩溃、真实新证据、同错误恢复等夹具产生不同且准确的结果；取消后无孤儿进程；不依靠制造假 Fact 推进状态。

**由用户决定：** 连续失败处理方式、重试次数、退避与无进展时间窗。上游“连续 5 次”只作为来源明确的候选值，本方案不自动套用。须保留现有用户预算和暂停语义。

### D05：hint、standby、resume 与重启恢复

**依据与范围：** 既有记录出现无 winner 时回退 claude、hint 传递损失和恢复失败；需要重新复现当前状态。涉及 `apps/web/drivers.py`、`run_manager.py`、控制日志、Worker 会话及容器路径映射；上游新 run_recovery 不能原样拼接到旧状态模型。

**拟实施：** 为“运行中提示、完成后询问、未解出后继续、服务重启”建立明确状态与测试；优先沿用已配置 dsh 身份/端点和可信会话，无法复用时明确选择新会话。人工指令直接交付并记录确认，不只依赖 planner 转述。恢复隔离环境、预算和已完成动作时采用稳定标识防止重复计入或重复执行。

**验收：** 只启用 dsh、无 winner、只读 follow-up、长指令、控制面重启、执行结果不确定等场景；确认不会误用云端引擎，不会把一次有状态请求重复执行，不改变已接受 Flag 的证据。

**由用户决定：** 恢复失败后允许自动新开 Worker，还是保持暂停等待决定；哪些操作允许重试。先保存会话/状态快照，分阶段迁移，不直接改写全部历史会话。

### D06：技能路由、版本与安全刷新

**依据与范围：** 已修中文词丢失并支持 domain 过滤；泛词仍可误命中 XSS；旧 Worker 目录不会覆盖更新；可选技能复制异常还可能被忽略。涉及 `kbsearch.py`、`search_terms.json`、`worker_skills.py` 与相关观测事件。

**拟实施：** 结合题型和当前症状选择相关章节，低置信结果作为候选而非确定方向；记录检索、实际读取及使用的不同阶段。技能源有固定版本与内容指纹；只刷新可证明由系统生成且未被用户修改的副本，冲突则保留并报告。准备失败提供可见原因，保持离线可用的索引路径。工具清单来自 doctor/验收结果，按题型交付实际入口。

**验收：** 中英混合、同义词、模糊查询、无命中、过期副本、用户修改、只读目录、缺失工具均可复现；“读取了资料”和“完成了相应操作”分列，不能用加载次数代替成功率。

**由用户决定：** 优先修检索路由还是先做版本刷新；正在运行的 Worker 是否保持原快照直到结束。推荐先冻结运行中的快照，更新只影响新 Worker。

### D07：Worker 资源与产物预算

**依据与范围：** 工具与本地模型共用内存/CPU，当前缺乏与任务类型一致的完整限制。涉及容器参数、运行控制、配置/健康视图、输出保存与产物管理。

**拟实施：** 统一配置 CPU、内存、PID、输出、工作目录空间与墙钟预算，并把有效值交付给运行和健康检查。大型日志落盘并保留索引，内存中只放必要视图；OOM、超时、空间不足分别报告。主机模型资源与 Worker 容器资源分别计量。

**验收：** 超限时能准确终止/报告，不误报成“题目失败”；Ghidra/Sage/PCAP 等代表操作在选定限制内可执行；已有证据产物不因清理被删除。

**由用户决定：** 具体 CPU/内存/PID/磁盘/输出/时间上限及保留策略。上游 full 的 2GB、2CPU 是其默认值，不能从本机 min/max 或工具清单直接推出适用上限。任何历史产物删除另行明确范围。

### D08：本地用量统计与预算一致性

**依据与范围：** 上游修复未知模型套通用美元单价及恢复后统计问题；本地仍需协调 cost、会话持久化、事件和 UI，不能只把价格置零。

**拟实施：** 将“未定价”“明确零 API 费用”“已有精确单价”分开；本地模式优先展示墙钟、输入/输出 token、缓存及调用次数，明确各模型后端的统计口径。每次用量有稳定标识，恢复后不丢失也不重复累加。美元预算遇到未定价模型时明确说明不可执行，电费/硬件成本不凭空估算。

**验收：** 未知模型、明确零价、缓存命中、缺失 telemetry、重复事件、恢复与多次尝试分别验证；前端展示与预算使用相同口径。

**由用户决定：** 本地运行需要哪些硬预算，是否保留美元显示；缺失统计如何标记。与 D04 的终止策略、D07 的墙钟/资源限制分别负责，避免重复权威。

### D09：精选离线技能、算法和专项工具

**依据与范围：** 工具审计为 32 PASS、3 MISSING，但部分仅验证启动；缺失项不应自动全部安装。扩展现有 `ctf_tools.py` 和项目级技能包，保留来源、许可、固定版本及可离线安装的依赖清单。

**可独立选择的子包：**

| 子包 | 内容 | 主要代价与验收 |
|---|---|---|
| D09-A 取证/编码 | PCAP 流重组、文件导出、QR/隐写入口 | 用字节级夹具验证产物；先确定现有 Python 工具能否替代缺失 CLI |
| D09-B Crypto | 精选 ctf-skills、crypto-attacks、RsaCtfTool 与参数检查 | 验证数学前提、固定依赖；排除 FactorDB 等在线路线 |
