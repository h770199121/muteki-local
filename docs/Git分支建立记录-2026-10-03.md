## 6. 维护约定

1. **上游用哈希固定，不写分支名。** 上游工作树有并发变更，`main` 会漂移。
2. 每次批量改动前确认 `git status` 干净；改动单独成提交，便于二分定位。
3. `origin` 与 `upstream` 同指上游仓库。离线环境下 `push` 不会成功；若日后在 GitHub 建真 fork，把 `origin` 改指向你的 fork 即可，`upstream` 保持不变。
4. 大目录不入库，其内容以路径 + 哈希记录在 `data/change-backups/batch0-20261003/manifest.sha256`（该目录本身也被忽略）。
5. **提交前扫凭据**：用逐文件字节比对，不要用 `git diff | grep`。
