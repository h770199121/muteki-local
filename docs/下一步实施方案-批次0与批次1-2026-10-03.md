## 3. 批次 1：四项修复（复核文档推荐范围）

复核文档第 7 节明确"首批推荐范围：A01 + A02 + A03 + A04，连同 D11 证据冻结和必要定向回归"。本节逐项落到可执行粒度。

### A01 — 评测 token 重复累计

**性质**：评测脚本缺陷，**不影响产品运行时**。但它污染一切基线数字，必须先修。

**根因**（`labs/nyu-ctf/run_challenge.py:241-245` 与 `334-341`，两处重复）：

```python
cost_events = [e for e in events if e.get("event_type") in ("cost.update","cost_update")]
tokens_in  = sum((e.get("payload") or {}).get("input_tokens", 0) for e in cost_events)
```

事件流中同时存在 solver 级累计快照与 challenge 级累计快照，直接 `sum()` 导致：① 同一 solver 前后快照被累加；② solver 与 challenge 层级双算。

**实施**：

1. 新建 `labs/nyu-ctf/usage_reduce.py`，作为**唯一**归约入口。核心规则：
   - 按 `(solver_id, scope)` 分组，组内**只取最后一条**累计快照，不累加。
   - solver 与 challenge **不跨层相加**——challenge 级若已覆盖该 solver，则跳过该 solver 的独立条目。
   - 输出必带 `coverage` 字段（哪些 solver 有独立账本、哪些仅 challenge 级上报）与 `telemetry_complete`（是否存在缺失估算）。
   - 历史事件无法无歧义重建时，`incomplete=True` 并说明缺口，**不输出一个看似精确的总数**。
2. 两处分支改为调用该入口，删除内联 `sum()`。
3. 统计版本化：结果新增 `"usage_stats_version": 2`，旧 `results.jsonl` 原样保留，新结果另写。

**验收**（标准库 unittest，新建 `tests/test_usage_reduce.py`）：

- 同一累计事件重复出现 N 次 → 用量不增加。
- solver + challenge 混合 → 不双算。
- 乱序输入 → 与有序输入结果一致。
- 缺 telemetry → 标 `telemetry_complete=False`，不静默按 0 处理。
- **重放 `run-20670.jsonl`：不得再出现 6,312,289 / 185,575 作为总量**（该值仅可作为"错误口径的历史值"留档对照）。

### A02 — 评测成功判据绕开真实执行来源

**性质**：评测脚本缺陷。产品 `gate.py` 未失效——run-20670 本身仍是未解出，本项不改判历史结论。

**根因**（`run_challenge.py:241`、`335`）：

```python
flag_found = ch["flag"] in json.dumps(events)   # 任何文本命中即 solved
```

复现已确认：仅含 `text.delta` 的合成事件、无论文工具执行、无论 Flag 接受事件，该表达式仍返回 True。题意、hint、模型猜测均可触发。

**实施**：

1. 成功判定改为**可信终态入口**：只接受 gate 接受事件 / 题目验证器结果，且能回查真实 tool output 或产物路径。
2. 三态分离记录：`candidate_found`（模型产出中出现过 flag 形状串）/ `gate_accepted`（Flag gate 接受）/ `external_verified`（外部判题器确认）。`solved` 只由后两者之一为真时置位。
3. 已知答案 `ch["flag"]` **只供 evaluator 比对，不得进入 Worker 输入**——检查该值当前是否被拼进 prompt，这是 A02 的隐藏入口，须一并切断。

**验收**（`tests/test_usage_reduce.py` 或独立 `tests/test_eval_verdict.py`）：

- 普通文本 / hint 含答案 → 仍失败。
- 真实来源但 gate 拒绝 → 不算接受。
- 来源、接受记录、attempt 三者对应 → 才成功。
- 多 Flag 按不同 Flag 与题目要求分别计数。

### A03 — hint 例外过宽，绕过 URL 凭据封存

**性质**：**安全相关，优先级最高**。这是本轮唯一涉及凭据泄露的项。

**根因**（`apps/web/control_adapter.py:251-253`）：

```python
elif (skey in free_text_keys and isinstance(value, str) and value
      and not value.startswith("secret://")):
    secured[skey] = value          # ← 直接保留，跳过 _redact_value()
```

`free_text_keys` 由 `306-313` 传入 `{"text","hint"}`（`_FREE_TEXT_ACTIONS`）。该分支跳过的不只是"内容关键词启发式"，而是**整个 `_redact_value()`**，因此 `http://user:password@host/` 的 URL userinfo 也不再封存，并可经 `safe_hitl_echo()`（`345-355`）明文回显。

这与第二轮 D05-② 的设计意图（"URL userinfo 仍保留封密"）**不符**——实现比意图宽。

**实施**（保持"普通 hint 可用"与"明确凭据载体必须封存"的分离）：

1. `free_text_keys` 分支不再整体跳过，改为**分层处理**：
   - 概念性提及（"password"、"token" 等词出现在叙述中）→ 放行，这是该分支存在的目的。
   - 明确凭据载体 → 仍走封存：URL userinfo（`scheme://user:pass@host`）、显式 `secret://` 引用、结构化密钥字段（`*_password`/`*_token`/`api_key` 等）、`ANSWER_DECISION` 的 answer。
2. 判定用**载体形态**（正则/结构），不用**关键词集合**——这是修复的根本分界。
3. 秘密输入沿现有安全交付链处理；dsh 不支持安全通道时返回可理解的明确错误，**不得退回明文日志**（这是第二轮 D05-② 想避免的 `SecurePromptUnsupported` 问题，需给明确报错而非静默降级）。

**验收**（新建标准库 unittest，**不能**复用 `test_control_secrets.py`——它依赖 pytest/pydantic，本机跑不了）：

同一组夹具必须同时覆盖 6 类：① 普通提示含 password 一词 → 放行；② `http://user:pass@host/` → 封存；③ 结构化密码字段 → 封存；④ 显式 `secret://` → 保持引用；⑤ answer/ANSWER_DECISION → 强制封存；⑥ 日志回显不含明文。**7 类需覆盖重试路径。**

### A04 — Worker 计量模型身份错误 + 未知模型套美元单价

**性质**：两个独立缺陷。第二轮审计只发现了第二个，**遗漏了更严重的第一个**。

**缺陷 1（更严重）** — `cli_solver.py:6923-6940` `_stream_cost()`：

```python
model = (str(getattr(self, "model", "") or "").strip()
         or str((getattr(self, "profile", None) or {}).get("model") or "").strip()
         or str(os.environ.get("MUTEKI_WORKER_MODEL") or "").strip()
         or "deepseek-v4-flash")            # ← 兜底
```

`self.model` / `self.profile` 在构造器未设置；Worker 专属环境也不同于父进程。实际配置模型为 `qwen3.8-27b`，走不到前两分支时**会落到 `deepseek-v4-flash`**——即按 flash 费率记账。复核文档已函数级复现，本方案再次确认代码路径成立。

**缺陷 2** — `cost.py:105-109` `price_for()` 兜底 `_DEFAULT_PRICE`（`$1/$3 per 1M`）。即使传入正确的 `qwen3.8-27b` 仍套通用单价（1M in + 100K out 夹具计 $1.30）。

**实施**（顺序很重要，缺陷 1 必须先修）：

1. **统一模型身份解析**：在 Worker 构造时确定 `effective_model`，取自 `self.driver.profile["model"]`（配置权威源）。`_stream_cost()`、健康检查、事件上报、计量**共用同一解析结果**，不再各自兜底。
2. **删除 `deepseek-v4-flash` 硬编码兜底**。取不到身份时显式标记为"未知"并走缺陷 2 的未定价语义，**不得静默套用他人费率**。
3. **未定价语义**（借鉴上游 `usage.py:60` 的 `unpriced_calls` 契约，**不直接拼进旧数据流**）：
   - 区分四态：① 明确零 API 费用（本地模型）② 未定价 ③ 精确单价 ④ 缺失/估算 telemetry。
   - 本地模型记 token 统计，USD 记为"不适用"而非 $0（$0 会被误读为"免费"，掩盖未定价事实）。
   - USD 显示、预算准入、持久化、settlement、恢复**共用同一语义**。
4. **注意预算门控交互**：`coordinator_loop.py:1045-1057` 墙钟检查在 USD 检查**之前**且独立。改 USD 语义时**不得触碰墙钟逻辑**——run-20670 正是墙钟终止（`elapsed=1201` / `1200`）。

**验收**（`tests/test_cost.py` 扩展，标准库）：

- dsh profile 模型与记账模型一致（构造 Worker → 断言 `effective_model`）。
- 取不到身份时不落 `deepseek-v4-flash`；标记为未定价。
- 显式零价仍保留 token 统计。
- 重复/恢复不重计。
- USD、墙钟、Worker 数三类预算**相互独立**——改 USD 不影响墙钟触发。
