## 2. 批次 1：四项修复（已完成）

### A03 — hint 例外过宽，绕过 URL 凭据封存 ✅

**安全相关，优先完成。**

根因确认：`_FREE_TEXT_ACTIONS`（HINT/ASK/FOCUS/DIRECTIVE/CORRECTION）的 `text`/`hint` 在 `control_adapter.py` 中**整体跳过** `_redact_value()`，而非仅跳过内容启发式。docstring 承诺的"URL userinfo 仍封存"在实现中不成立。

**实施中发现的第二个缺陷（复核文档与前次审计均未指出）**：

`_URL_USERINFO` 正则以 `^` 锚定，要求 URL 位于字符串开头。实测：

```
MATCH  'http://user:password@host/'
MISS   'try http://user:password@host/'      ← 嵌在句子里就漏
MISS   'see http://u:p@h/ now'
```

而 hint 的典型形态**正是**自然语句。所以即使当初实现了 free-text 分支，嵌入句子的凭据 URL 依然会泄露。这是独立于分支逻辑的第二个根因。

修复：
1. 新增 `_is_credential_carrier(key, value)` —— 按**载体形态**判定（`secret://` 引用、URL userinfo、结构化凭据键），而非按关键词。
2. free-text 分支加条件 `and not _is_credential_carrier(skey, value)`，只豁免内容启发式。
3. `_URL_USERINFO` 去掉 `^` 锚定，改用 `(?<![\w@.-])` 前向边界。

保持不变：普通 hint 提到 "password"/"密钥" 仍然放行（这是该分支存在的目的，也是 run-18655 `SecurePromptUnsupported` 的修复依据）。

验证：`tests/test_a03_free_text_sealing.py` **16 项通过**，覆盖 6 类夹具 + 重试 + 源码契约。**反向验证**：对修复前代码跑同一测试，失败于"缺少被测定义 `_is_credential_carrier`"——证明测试确实锚定真实代码路径。

由于本机无 pydantic，该测试用 AST 从**真实源文件**抽取被测逻辑执行，不是复制粘贴，测试不会与实现脱节。

### A01 — 评测 token 重复累计 ✅

**模块**：`labs/nyu-ctf/usage_reduce.py`（新增，唯一归约入口）
**接入**：`run_challenge.py` 两处分支均已替换，删除内联 `sum()`

run-20670 的 8 条 `cost.update` 事件结构已核实：`scope` 字段区分 `solver`/`challenge`，且都是**累计快照**。

| 口径 | input | output |
|---|---:|---:|
| 旧实现（直接 sum 全部累计事件） | 6,312,289 | 185,575 |
| **本模块（solver 台账）** | **1,563,948** | **52,737** |
| challenge-scope 快照（另一层级，不相加） | 1,099,455 | 36,243 |

归约规则：按 `(scope, identity)` 分组取最后快照；solver 与 challenge **不跨层相加**；`execution_generation` 较大者优先（覆盖 resume 场景）。

**诚实性设计**：当 challenge rollup 小于 solver 合计（说明有 solver 在 rollup 之后启动、其用量只在别处可见）时，输出 `telemetry_complete=False` 并说明缺口，而不是给一个看似精确的数字。run-20670 正是这种情况。

验证：`tests/test_usage_reduce.py` **18 项通过**，含真实归档重放（断言不再出现 6,312,289/185,575）。

### A02 — 评测成功判据绕开真实执行来源 ✅

**模块**：`labs/nyu-ctf/eval_verdict.py`（新增）

缺陷复现（修复前）：仅含 `text.delta`、无任何工具执行的合成事件，旧表达式 `ch["flag"] in json.dumps(events)` 返回 **True**。

新判据三态分离：
- `candidate_found` —— flag 串出现过（最弱，仅文本）
- `gate_accepted` —— Flag gate 接受，且**有工具执行证据**
- `external_verified` —— 外部判题器确认

`solved` 只由后两者置位。另外：接受事件若缺少执行证据则**不被采信**；上一次 attempt/generation 的接受记录不沿用；被拒候选永不计入。

**顺带核实 docstring 承诺**：全文件搜索确认 `ch["flag"]` 仅出现在两处判分调用，**未进入 Worker prompt 或 API 请求**。

验证：`tests/test_eval_verdict.py` **17 项通过**，含"run-20670 未解出不得被翻转"。

### A04 — Worker 计量模型身份错误 + 未知模型套美元单价 ✅

**两个缺陷，先身份后定价。**

缺陷 1（更严重）：`_stream_cost()` 的模型兜底链读 `self.model` / `self.profile`——**这两个属性在 CliSolver 上从未被赋值**（全类仅 `self.driver`），父进程环境亦不同，最终落到硬编码 `"deepseek-v4-flash"`。实际配置 `qwen3.8-27b` 因此被按 flash 费率记账。

修复：新增 `CliSolver.effective_model()`，以 `driver.profile["model"]`（`ProfileDriver`/`EndpointDriver` 均为模型权威，含嵌套 `base`）为唯一权威；**删除硬编码兜底**，取不到时返回空串 → 记为未定价。

缺陷 2：`price_for()` 兜底 `_DEFAULT_PRICE`（$1/$3 per 1M）。

修复：删除该常量；新增三态语义
- `exact` —— 已知单价
- `local_zero_api_cost` —— 本地端点，无 API 账单（**与"未知"可区分**）
- `unpriced` —— 价格未知，不编造

`record()` 保留 token 统计、`usd=0`、并累计 `unpriced_calls`；`COST_UPDATE` 事件新增 `pricing_status` / `priced_model` / `unpriced_calls` 字段（**仅新增，不改既有键**，评测器仍按 input/output 取值）。

**未触碰墙钟逻辑**：`test_cost_pricing.py` 显式断言 `coordinator_loop.py` 中 `wall_clock_budget_exhausted` 仍存在且未用 USD 表达。run-20670 终止于 `elapsed=1201` / `wall_budget_s=1200`，该行为必须保持。

顺带修复 `cli_driver.py:1046` 对已删除 `_DEFAULT_PRICE` 的引用（改为显式 None 处理）。

验证：`tests/test_cost_pricing.py` **15 项通过**，含身份解析器从真实源码抽取执行。
